## 먼저 만날 말 · 업무에 빗대어 보기

이름보다 **무슨 일을 할 때 쓰는지**만 봅니다. 뒤에서 직접 써 볼 때 다시 연결하겠습니다.

### AI 기본 개념과 짧은 역사

AI는 큰 우산, 머신러닝은 사례에서 배우는 방법, 딥러닝은 여러 층의 신경망으로 배우는 방법, LLM은 글을 다루는 모델입니다. **Claude는 LLM을 사용하는 AI**예요.

**AI**기계가 글쓰기·분류·예측 같은 일을 하게 하는 큰 분야포함 관계 예시 →**머신러닝 · ML**사례를 보며 패턴을 배우는 AI 방법그중 한 방법 →**딥러닝**여러 층의 신경망으로 복잡한 패턴을 배우는 머신러닝글을 다루는 모델 →**대규모 언어 모델 · LLM**많은 글을 바탕으로 다음에 올 말을 예측해 문장과 코드를 만드는 모델

쉬운 관계 그림입니다. 모든 AI가 머신러닝인 것은 아니며, AI에는 규칙을 직접 정하는 방법도 있습니다.

[](assets/49-ai-history-journey.png)AI의 변화를 상징적으로 그린 삽화입니다. 실제 역사 사진은 아닙니다.

대표 장면으로 보는 AI의 흐름
- **1950 · 질문을 던지다**앨런 튜링이 기계가 생각할 수 있는지 묻고, 대화로 판단하는 아이디어를 제안했습니다. [원 논문](https://academic.oup.com/mind/article/LIX/236/433/986238)

- **1956 · AI라는 이름이 자리 잡다**다트머스 연구 모임에서 ‘Artificial Intelligence’라는 이름을 내걸고 연구를 시작했습니다. [다트머스 자료](https://home.dartmouth.edu/about/artificial-intelligence-ai-coined-dartmouth)

- **2012 · 딥러닝이 주목받다**신경망이 이미지 분류에서 큰 성과를 내며 딥러닝 연구가 빠르게 확산됐습니다. [AlexNet 논문](https://papers.nips.cc/paper_files/paper/2012/hash/c399862d3b9d6b76c8436e924a68c45b-Abstract.html)

- **2017 · 트랜스포머가 나오다**문장 속 단어 관계를 살피는 구조가 제안되어 오늘날 LLM 발전의 중요한 바탕이 됐습니다. [원 논문](https://arxiv.org/abs/1706.03762)

- **2022 · 대화형 AI를 널리 경험하다**ChatGPT가 공개 연구 미리보기로 출시되어 사람들이 대화로 AI를 쓰는 경험을 널리 알렸습니다. LLM 연구 자체가 이때 시작된 것은 아닙니다. [OpenAI 발표](https://openai.com/index/chatgpt/)

## 04. 바이브 코딩 · 의도·기획·프롬프트

**이번에 할 일** 내가 만들 도구와 완료 기준을 짧게 말합니다.

### 개념 바이브 코딩 · 말로 만들고 다듬기

AI 연구자 **안드레 카파시**가 2025년에 소개한 말입니다. 코드를 직접 자세히 쓰거나 읽기보다, 원하는 모습을 AI에게 말하고 결과를 보며 만드는 방식을 가리켰습니다.

예: “버튼을 누르면 숫자가 올라가게 해줘” → 실행 → “버튼을 더 크게 해줘”.
오늘은 말로 만들어 보고, 동작은 직접 눌러 확인합니다. [카파시의 설명](https://karpathy.bearblog.dev/year-in-review-2025/)

**의도는 만들고 싶은 이유**입니다. “멋진 앱”보다 “남은 일을 놓치지 않게”라고 말해 보세요. 여기에 넣을 정보와 완료 기준을 더하면 작은 기획이 됩니다.

[](assets/31-의도에서첫작업.png)불편을 정하고, 작은 작업 하나만 맡기고, 결과는 내가 확인합니다. AI 생성 설명 그림.

### 좋은 프롬프트 예시부터 볼까요?

“회의 메모를 줄게. 결정한 일과 담당자별 다음 일을 표로 정리해줘. 메모에 없는 담당자는 ‘미정’으로 두고, 빠진 내용이 없는지 원문과 비교해줘.”

- **줄 자료:** 회의 메모

- **만들 것:** 결정 사항과 담당자별 할 일 표

- **확인:** 빠진 내용은 없는지 원문과 비교

### 개념 부탁할 때는 세 칸만

좋은 프롬프트는 **무엇을 줄지 · 무엇을 만들지 · 어떻게 확인할지**를 알려 줍니다. 위 예시처럼 업무와 확인 기준을 한두 문장으로 적으면 됩니다. 간단한 첫 시연은 만들 것만 말해도 괜찮습니다.

그런데 처음부터 세 칸을 혼자 채우기는 어렵습니다. **무엇이 필요한지 AI에게 먼저 물어보게 하고, 내 답으로 프롬프트를 써 달라고 하면 됩니다.** 이 방법을 메타프롬프팅이라고 부릅니다.

**막막할 때 붙여 넣을 프롬프트**

“회의 메모를 정리하는 일을 줄이고 싶어. 필요한 걸 하나씩 물어보고, 내 답으로 짧은 프롬프트를 써줘. 아직 실행하지는 마.”

파일을 참고시키려면 **@를 입력하고 목록에서 파일을 고릅니다**. 예: @workbooks/주간비용_실습.xlsx. 저장할 위치는 처음에는 Claude Code가 제안하도록 두어도 됩니다.

[](assets/44-프롬프트-세칸.svg)처음부터 혼자 다 정하지 않아도 됩니다. 막막하면 AI에게 질문부터 시키세요.

### 개념 프롬프트 네 가지 모양

앞으로 나오는 프롬프트는 대부분 아래 네 가지 중 하나입니다. 한 줄에 너무 많은 일을 섞지 않습니다.

- **바로 부탁하기** · 할 일이 분명할 때
“누르면 숫자가 1씩 올라가는 웹페이지를 간단하게 만들어줘.”

- **물어보고 바로 만들기** · 기준을 아직 못 정했을 때
“필요한 기능을 하나씩 3개까지 물어봐 줘. 내가 고른 기능만 만들어줘.”

- **프롬프트도 써 달라고 하기 (메타프롬프트)** · 뭐라고 말할지 모를 때 (만들지 않고 프롬프트만 받습니다)

## 05. 에이전트부터 에이전틱 코딩까지

**이번에 할 일** AI가 하는 일과 내가 확인할 일을 구분합니다.

### 개념 에이전트 · 목표를 주면 방법을 정하고 일하는 AI

AI에게 목표를 주면, 필요한 일을 나누고 **허용된 도구로 작업한 뒤 결과를 확인**합니다. 이런 방식으로 일하는 AI를 에이전트라고 부릅니다. 내가 원하는 결과와 맡길 범위를 먼저 알려 줍니다. [공식 설명](https://www.anthropic.com/engineering/building-effective-agents)

**① 내가 목표 정하기**“숫자 버튼을 만들어줘.”

**② AI가 작업하기**계획 → 파일 만들기 → 동작 확인

**③ 내가 결과 보기**브라우저에서 버튼을 눌러 보기

업무에서도 같습니다. **“이 회의 메모를 팀장용 회의록으로 정리해줘”**라고 맡기면 메모를 읽고, 결정과 할 일을 정리하고, 파일로 저장하게 할 수 있습니다. 모르는 담당자나 날짜는 내가 알려 줍니다.

**Claude·Cowork·Claude Code · 차이가 궁금하면**

**Claude는 AI와 서비스의 이름**입니다. 아래는 같은 AI를 어떤 방식으로 쓸지 비교한 예시입니다.

| 이름 | 주로 맡길 일 | 회의 메모로 예를 들면 |
| --- | --- | --- |
| **Claude 일반 대화** | 질문·아이디어·문장 다듬기 | “이 메모에서 중요한 내용이 뭐야?” |
| **Claude Cowork** | 파일과 연결 도구를 써서 업무 결과물 만들기 | “이 메모들을 읽고 회의록 파일로 정리해줘.” |
| **Claude Code** | 파일·코드·명령을 다뤄 도구를 만들고 반복 실행하기 | “메모를 넣으면 같은 양식의 회의록을 만드는 도구를 만들어줘.” |

일반 대화에서도 파일을 만들 수 있습니다. 일부 계정은 Chat과 Cowork가 한 대화 화면으로 통합되어 보입니다. 이름보다 **무엇을 맡기고 어떤 결과를 받을지**로 고르면 됩니다. [Claude·Cowork 공식 안내](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)

이번 수업은 **터미널에서 Claude Code**를 사용합니다. 한국어로 부탁하면 실습 폴더에 파일을 만들고 명령을 실행하며, 내가 다시 쓸 업무 도구를 만들어 봅니다. [Claude Code 공식 안내](https://code.claude.com/docs/en/overview)

### 개념 에이전틱 코딩 · 실행까지 맡기기

이 에이전트 방식으로 **코드와 업무 도구를 만들고 고치는 것**이 에이전틱 코딩입니다. AI가 계획 → 파일 작업 → 실행 → 확인을 이어가고, 나는 원하는 결과를 정하고 직접 써 봅니다.

예: “체크리스트를 만들고, 추가·완료·새로고침이 되는지 확인해줘.”

### 모드와 권한

[](assets/35-Claude-모드선택.png)Claude Code 편집기 화면의 모드 메뉴 예시 · 터미널에서는 Shift + Tab으로 전환

- **Plan:** 먼저 계획을 봅니다. 큰 변경이나 처음 하는 작업에 씁니다.

- **Manual · 수동:** 작업하며 필요한 권한을 묻습니다.

- **Edit automatically · 편집 허용:** 파일 편집을 자동으로 허용합니다. 명령 실행에는 별도 확인이 필요할 수 있습니다.

- **Auto:** 작업의 안전성을 자동으로 확인하고, 위험한 행동은 멈춰 확인받습니다.

`Shift + Tab`으로 모드를 바꿉니다. 사용 가능한 모드는 설치 버전과 계정에 따라 다를 수 있습니다. [모드 안내](https://code.claude.com/docs/en/permission-modes)

**처음 만들 때:** Manual(수동)에서 시작해 권한 창을 읽어 봅니다. Plan에서 계획을 확인했다면, 승인 화면에서 편집을 허용해 만들기를 시작합니다.

권한 창에서는 **대상 파일과 할 일**을 읽습니다. 실습 폴더에 결과를 만드는 작업은 확인 후 허용하고, 원본 삭제나 메일 발송은 거절합니다.

- 한국어로 쉬운 질문을 한 번에 하나씩 하고 답을 기다린다. 이미 알려 준 내용은 다시 묻지 않는다. 최대 3개 질문으로 필요한 내용을 정한다.

- 질문에는 추천 선택지와 자유롭게 답할 여지를 준다. 최종 선택은 사용자가 한다. 기능은 최대 3개, 화면은 1개로 줄이고 나머지는 다음 개선으로 남긴다.
- 이 실습은 HTML 한 파일, 외부 라이브러리·API·서버·로그인 없는 범위다. 범위를 넘는 기능은 구현 가능한 작은 대안을 함께 제안하고 선택을 기다린다.

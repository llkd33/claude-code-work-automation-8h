# 아주 작은 카운터 스펙 · 강사 시연용

이 파일은 오전 3H 설명·강사 시연에서 참조하는 텍스트 문서입니다. `.md` 파일 자체는 프로그램을 자동 실행하지 않습니다. 학생의 오후 첫 제작은 기존 체크리스트이며 카운터를 별도 추가 실습으로 요구하지 않습니다.

카운터는 누르면 숫자가 올라가는 작은 도구입니다. 카운터 스펙은 이 도구가 지켜야 할 규칙을 적은 문서입니다. 이번 규칙은 처음 0, 누를 때마다 +1, 새로고침하면 0입니다.

## 카운터 스펙

### 의도와 원문 기준

버튼을 누르면 숫자가 변하는 가장 작은 화면으로 스펙 → 계획 → 사람 확인 → 구현 → 검사 흐름을 보여 줍니다. 이 절에 적힌 요구가 이번 카운터의 원문 기준입니다. 아래의 직접 요청 비교는 다른 대화·다른 결과 파일의 안내이며 이 스펙에 추가할 기능이 아닙니다.

### 대상·입력·동작

- 대상: 처음 작은 HTML 도구의 동작을 확인하는 수강생.
- 입력: 화면의 `+1` 버튼을 한 번 누릅니다.
- 처음 화면을 열면 숫자는 **0**입니다.
- 버튼을 한 번 누르면 현재 숫자가 **정확히 1 증가**합니다. 여러 번 누르면 누를 때마다 1씩 증가합니다.
- 브라우저에서 **새로고침하면 다시 0**입니다. 닫았다 다시 열어도 0에서 시작합니다.
- 숫자를 저장하지 않습니다. localStorage·쿠키·DB 등 저장 기능을 넣지 않습니다.

### 화면·파일·범위

- 화면은 **1개**이며 표시 숫자와 `+1` 버튼을 읽기 쉽게 배치합니다.
- 실제 결과 파일은 **`output/demo/spec-counter.html`** 하나입니다. CSS와 JavaScript도 이 HTML 안에 둡니다.
- 파일을 브라우저에서 직접 열어 사용합니다. 서버를 만들거나 실행하지 않습니다.
- 로그인, 웹검색, 외부 API, 새 MCP, 추가 패키지 설치를 포함하지 않습니다.
- 초기화 버튼, 감소 버튼, 기록 목록, 자동 증가, 화려한 애니메이션 등 추가 기능은 이번 범위에 넣지 않습니다.

### 예외·미정·수정 이력

- 한 번의 클릭으로 2 이상 증가하거나 값이 NaN으로 바뀌면 실패입니다.
- 새로고침 뒤 이전 숫자가 남아 있으면 실패입니다.
- 미정: 없음. 화면 색상·간격 등은 읽기 쉬운 수준으로 정하며 기능 범위를 바꾸지 않습니다.
- 수정 이력: 초기 작성본입니다. 시작 0·클릭마다 1 증가·새로고침 뒤 0을 이번 시연의 명시 기준으로 적었습니다. 이후 기준 변경이 생기면 변경 이유와 사람이 확인한 내용을 먼저 기록합니다.

### 구현 계획과 사람 확인

계획은 **3줄 이내**로 설명합니다. 파일 위치, 숫자·버튼 동작, 검사 순서가 들어가면 충분합니다. **계획을 설명한 뒤 사람의 확인을 기다리고, 확인 후 구현**합니다. 아직 확인받지 않은 상태에서 파일을 만들거나 수정하지 않습니다. 이 대기 단계는 이번 강사 시연의 진행 규칙입니다.

### 검사항목 3개

1. **시작:** 결과 파일을 브라우저에서 처음 열면 0이 보이고 `+1` 버튼이 있습니다.
2. **증가:** 버튼을 한 번 누르면 1, 두 번 더 누르면 3이 됩니다. 매번 정확히 1씩 증가합니다.
3. **새로고침:** 3인 상태에서 브라우저를 새로고침하면 0이 됩니다. 저장 기능이 없는 기준과 일치합니다.

세 항목을 실제로 확인한 결과와 미확인 항목을 구분해 보고합니다. 파일이 생성되었다는 사실이나 AI의 “완료” 문장만으로 동작 검사를 통과했다고 기록하지 않습니다. 실패한 동작을 수정한 뒤 영향을 받은 검사항목을 다시 확인합니다.

## 강사의 파일 참조 요청 — Claude 대화에 입력합니다

작업 폴더는 `claude-work-lab`입니다. Claude Code 대화 입력칸에서 `@` 입력 → 경로 제안의 `templates/spec-driven/02_카운터_스펙.md` 선택 → Enter 또는 Tab으로 경로 확정 → 요청 완성 → Enter로 전송합니다. 첫 Enter는 파일 선택, 마지막 Enter는 요청 전송입니다. `@`는 파일 참조이며 `cd`나 셸 명령이 아닙니다.

```text
- @templates/spec-driven/02_카운터_스펙.md를 기준으로 숫자 버튼을 만들고 싶어.
- 먼저 만들 순서를 3줄로 알려줘.
- 아직 만들지 마.
```

계획을 읽고 확인한 뒤 별도 메시지를 보냅니다.

```text
계획을 확인했어. 카운터 스펙 범위대로 output/demo/spec-counter.html을 구현해 줘.
검사항목 3개를 확인하고, 실제로 검사한 것과 아직 미확인인 것을 구분해 알려줘.
```

## 비교 시연 — 직접 요청은 다른 대화·다른 파일입니다

강사는 스펙 시연과 **별도의 대화**에서 아래 직접 요청을 먼저 보여 줄 수 있습니다.

```text
버튼을 누르면 숫자가 올라가는 작은 카운터를 HTML 파일 하나로 만들어 줘.
결과는 output/demo/plain-counter.html에 저장해 줘.
```

직접 요청 결과는 `output/demo/plain-counter.html`, 스펙 결과는 `output/demo/spec-counter.html`입니다. 두 파일을 따로 열어 처음 값, 버튼 동작, 새로고침 동작을 관찰합니다. 한 파일을 다른 파일의 이름으로 덮어써 비교하지 않습니다.

두 요청의 정보량은 다릅니다. 직접 요청에는 시작값과 새로고침 기준이 빠져 있고 스펙에는 들어 있습니다. 따라서 이 비교는 스펙 형식만의 효과를 검증한 공정한 실험이 아닙니다. 직접 요청이 잘 작동할 수도 있고, 같은 상세 조건을 직접 요청에 적으면 비슷한 결과가 나올 수도 있습니다. **항상 스펙이 더 좋다는 결론을 내리지 않습니다.** 사람이 기준을 적고 계획과 결과를 확인하는 방식의 차이를 관찰합니다.

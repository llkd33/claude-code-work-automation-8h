# 내 주간 비용 보고

기본 기준 금액: 50000원. 내 업무에 맞게 이 값 하나를 고친다. 사용자가 이번 기준을 주면 그 값을 사용한다.

## 입력부터 결과까지

1. 입력 이름을 확인한다. 입력 별칭이나 출력 위치가 생략되면 templates/수업_파일안내.md의 /weekly-report 항목에서 기본 위치를 찾는다. 기준 금액은 이 스킬에 적힌 값을 쓴다. 안내로 정할 수 없는 정보만 최대 두 질문으로 확인한다. 원본은 수정하지 않는다.
2. integrations/local-report/README.md의 지원 열·수식·실행 방법을 읽는다. 처음에만 package 설치 상태를 확인하고, 준비되지 않았으면 사전 준비 안내로 돌린다. 설치 실패를 성공으로 표시하지 않는다.
3. `node integrations/local-report/weekly-report.cjs "입력경로" "출력폴더" --threshold 기준금액`을 실제 실행한다. 경로와 옵션은 쉘에 안전하게 전달한다. 절차 설명만 하고 끝내지 않는다.
4. 정상 종료 후 실제 summary.json·verification.json·share.txt를 읽고 report.html 존재를 확인한다. 총액=부서별 합, 건수=완료+진행, 원본 품질 검사 상태를 대조한다. 브라우저를 사용하지 못하면 화면은 미확인으로 남긴다.
5. 오류면 verification.json의 ok:false와 원인을 알려준다. 임의로 값을 0으로 바꾸거나 중복을 조용히 삭제하지 않는다. 마지막 정상 결과가 이번 입력의 결과가 아니라는 점을 표시한다.
6. 수정은 문제가 확인된 경우 해당 부분 1회, 재검수 1회까지만 한다. 계속 실패하면 오류와 남은 일을 기록하고 중단한다. 다른 파일과 외부 계정은 변경하지 않는다.
7. notes/weekly-report-result.md에 실제 입력·실행 명령·출력·검증 숫자·품질 상태·기준·미확인 항목을 10줄 이내로 기록한다. 정상 보고서와 오류 기록을 혼동하지 않는다.

## 확인

- 정상: 제공 원본은 40건. 다음 주 표도 헤더 이름으로 처리한다. 다른 입력에 샘플 정답을 강제하지 않는다.
- 오류: 중복 전표·빈 단가·필수 열 누락은 중단한다. 이전 정상 HTML·요약·공유 문안은 보존한다.
- 새 세션에서 /weekly-report를 실제 호출했는지 실행 기록으로 확인한다. 파일 존재만으로 호출 성공을 주장하지 않는다.

이 Skill은 반복 절차다. 데이터를 자동 최신화하거나 일정을 등록하지 않는다. 호출 시 AI 사용량이 발생하고, LLM 없는 계산 코드를 직접 실행하는 것과 구분한다.

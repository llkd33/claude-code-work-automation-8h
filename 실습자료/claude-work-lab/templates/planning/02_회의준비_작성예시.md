# 작성 예시 · 금요일 비용 마감 체크리스트

예시를 보고 내 말로 적습니다. 오늘은 화면 1개, 기능 최대 3개입니다.
빈칸은 AI에게 채우게 하지 않습니다. 완성 뒤 구현 요청과 함께 붙여 넣습니다.

## PRD · 만들기 약속

### 도구 이름
금요일 비용 마감 체크리스트

### 누가, 언제, 무엇이 불편한가요?
비용 담당자인 내가 금요일마다 정리·보고 준비를 빠뜨립니다.

### 꼭 할 기능 · 한 줄에 하나, 최대 3개
마감할 일 추가
끝낸 일 체크
새로고침 뒤 목록 유지

### 잘 만들어졌는지 직접 확인할 방법
2개 추가 → 1개 완료 → 새로고침 → 2개와 완료 표시 유지

## IA · 정보 묶음 지도

### 소개 묶음 · 무엇을 알려주나요?
도구 이름과 “금요일 마감 준비를 확인하세요” 안내

### 입력 묶음 · 무엇을 적거나 누르나요?
마감할 일 입력칸과 추가 버튼

### 결과 묶음 · 무엇을 보나요?
마감 목록과 완료 체크

## User Journey · 사람의 사용 이야기

### 시작 · 상황과 마음
금요일 마감 전 도구를 연다. “또 빠뜨릴까 걱정돼.”

### 사용 · 행동과 마음
정리·보고할 일 2개를 적고 끝낸 것에 체크한다. “차례대로 하면 되겠네.”

### 끝 · 결과와 마음
남은 일을 확인하고 마감을 준비한다. “이제 안심!”

## 구현 요청 · 위 계획을 채운 뒤 함께 복사
- - 위 계획은 내가 작성했습니다.
- - 이 계획으로 현재 폴더에 index.html 하나를 실제로 만들어줘.
- - 화면 1개, 내가 적은 기능 최대 3개만 구현해줘.
- - IA는 정보 묶음, User Journey는 사용 상황과 흐름으로 참고해줘.
- - 외부 라이브러리·API·서버·로그인은 쓰지 마.
- - 저장이 필요한 기능은 이 브라우저의 localStorage를 사용하고 실패하면 안내해줘.
- - 입력 텍스트를 HTML로 실행하지 마.
- - 기존 파일이 있다면 보존하고 새 파일명 하나를 알려줘.
- - 계획의 빈칸·모순이 있으면 임의로 정하지 말고 질문 1개로 확인해줘.
- - 결과는 변경 파일·여는 방법·내 확인 기준의 검사 방법만 짧게 알려줘.
- - 실제로 검사하지 않은 동작은 미확인으로 표시해줘.

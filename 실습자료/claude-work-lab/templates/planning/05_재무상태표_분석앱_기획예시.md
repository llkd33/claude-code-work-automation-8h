# 가상 재무상태표 분석 앱 · 기획 예시

교육용 예시입니다. 회사·수치·판정 기준은 모두 가상이며 실제 재무 판단에 쓰지 않습니다.

## 1. 문제 인터뷰 요약

- 사용자: 매달 재무상태표를 확인하는 소규모 회사 대표 또는 재무 담당자.
- 불편: 유동성 숫자를 계산하고 여러 달의 변화를 비교하기 번거롭다.
- 원하는 결과: 파일을 넣으면 현금 여력과 단기 지급 부담을 빠르게 살핀다.
- 미정으로 남길 점: 엑셀 열 이름, 분석할 기간, 지표 기준은 사용자가 답하기 전까지 정하지 않는다.

## 2. IA · 화면에 정보를 어떻게 묶을까?

| 화면 묶음 | 들어갈 내용 | 사용자가 하는 일 |
|---|---|---|
| 파일 넣기 | 파일 선택·드래그, 선택한 파일명, 업로드/분석 버튼 | 가상 재무상태표 선택 |
| 한눈 요약 | 핵심 요약 3줄, 자료 기간, 누락·검사 안내 | 먼저 결과를 파악 |
| 유동성 보기 | 유동비율·당좌비율·현금비율과 기간별 그래프 | 지표와 흐름 비교 |
| 신호 기준 | 초록·노랑·빨강 기준, 계산식, 기준 수정 | 기준을 확인하고 수정 |
| 개인정보 안내 | 파일을 Claude에 전달할지 확인하는 안내 | 전송 전에 동의하거나 취소 |

## 3. User Journey · 사용 순서

1. 사용자가 앱을 열고 가상 재무상태표 파일을 선택한다. 어떤 숫자가 Claude에 전달되는지 확인한다.
2. 동의하면 앱이 파일을 읽고 숫자 형식·필수 항목·자산=부채+자본을 검사한다. 오류가 있으면 분석을 멈추고 수정할 곳을 알려준다.
3. 계산 프로그램이 유동성 지표를 계산한다. Claude는 계산된 값만 보고 세 줄로 쉬운 설명을 만든다.
4. 사용자가 그래프와 신호등, 적용된 기준을 확인한다. 신호는 참고용이며 회사·산업에 따라 달라질 수 있음을 본다.
5. 사용자가 결과를 확인하고 로컬 파일로 저장하거나 닫는다. 외부 공유는 하지 않는다.

## 4. PRD · 첫 버전에서 만들 것

### 목표

월별 재무상태표 파일을 넣어 유동성 지표와 변화를 쉽고 빠르게 확인한다.

### 첫 버전 기능

1. XLSX 또는 CSV 예시 파일을 선택하거나 드래그앤드롭한다.
2. 자산·부채·자본 합계가 맞는지 검사하고, 계산 가능한 경우 유동비율·당좌비율·현금비율을 계산한다.
3. 세 지표의 기간별 그래프, 핵심 설명 3줄, 수정 가능한 신호등 기준을 보여준다.
4. 오류·빈 값·0인 분모가 있으면 임의로 채우지 않고 분석을 멈춰 이유를 표시한다.

### 계산 기준 예시

- 유동비율 = 유동자산 ÷ 유동부채 × 100
- 당좌비율 = (현금성자산 + 단기금융자산 + 매출채권) ÷ 유동부채 × 100
- 현금비율 = 현금성자산 ÷ 유동부채 × 100
- 이 예시의 “현금성자산” 범위와 각 계정 매핑은 사용자가 확인하고 바꿀 수 있다.
- 신호등은 편집 가능한 교육용 예시다. 보편적 정답·신용평가·투자 조언처럼 표현하지 않는다.

### 데이터와 기술 경계

- 앱 화면과 원본 파일은 수강생 PC의 Electron 앱에서 다룬다.
- Claude 설명 기능은 로그인된 Claude Code CLI를 부른다. 파일 일부/요약값이 Claude 서비스에 전달될 수 있으므로 어떤 내용이 전송되는지 실행 전에 보여주고 사용자가 매번 동의하게 한다.
- 동의하지 않으면 로컬 계산만 수행하고 AI 설명은 생략한다. API 키, 별도 로그인, 외부 앱 서버, 자동 이메일 발송을 추가하지 않는다.
- 수업에서는 가상 자료만 쓴다. 실데이터 적용 전에는 회사의 보안·재무 검토를 거친다.

### 완료 확인

- Claude가 만든 가짜 6개월 표를 열어 기간별 그래프가 보인다.
- 자산 합계와 부채+자본 합계를 대조하고 차이가 표시된다.
- 세 지표가 위 식으로 계산되고, 기준을 바꾸면 신호가 달라진다.
- 열 이름 누락·잘못된 금액·유동부채 0에서는 오류를 알아보기 쉽게 표시한다.
- Claude 전송 전 동의창에 전달 항목이 표시되며, 취소하면 파일 내용이 Claude에 전달되지 않는다.
- 실제로 하지 않은 검사는 완료했다고 표시하지 않는다.

## 5. 구현 순서

1. 사용자 인터뷰를 최대 3문항으로 마친다.
2. 문제 정의를 확인받고 IA 초안을 승인받는다.
3. IA 승인 뒤 User Journey를 보여주고 승인받는다.
4. Journey 승인 뒤 PRD와 완료 확인 항목을 보여주고 승인받는다.
5. PRD 승인 후 Electron MVP를 만든다. 한 번에 모든 기능을 넣지 말고 파일 불러오기 → 계산/검사 → 그래프/요약 → Claude 설명 순으로 구현한다.
6. 가짜 파일로 각 단계 결과를 확인하고, 미완료 항목과 실행 방법을 기록한다.

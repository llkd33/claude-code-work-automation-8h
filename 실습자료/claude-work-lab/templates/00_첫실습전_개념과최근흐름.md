# 첫 실습 전에 이해할 개념과 최근 흐름

오전에는 개념과 강사 시연을 보고 오후에 직접 만듭니다. 이 문서는 07 첫 체크리스트 실습 전의 설명 자료입니다.

## 1. 코드, 프로그램, 파일, 화면
코드는 컴퓨터가 할 일을 적은 글입니다. 프로그램은 그 코드를 실행해 실제 일을 합니다. 파일은 메모·Excel·코드·보고서 같은 자료 한 개이고 폴더는 함께 쓸 파일을 모아 둔 위치입니다. 폴더로 이동했다고 파일이 실행되지는 않습니다.

index.html은 화면을 만드는 파일입니다. 브라우저가 읽으면 체크리스트가 보입니다. .md는 글과 제목·표를 적는 문서이고 .xlsx는 Excel 자료입니다. .cjs 같은 스크립트는 파일을 읽고 계산하는 절차를 실행합니다. JSON은 totalAmount 같은 항목 이름 옆에 값을 적어 둔 데이터 메모입니다. 그 파일을 읽는 프로그램이 표나 차트로 보여 줍니다.

### AI·머신러닝·딥러닝·LLM은 어떤 관계인가요?

| 용어 | 쉬운 뜻 | 익숙한 예 |
| --- | --- | --- |
| AI · 인공지능 | 판단·예측·글쓰기 등을 컴퓨터로 수행하는 기술의 큰 이름 | 사진 분류, 상품 추천, 글 요약 |
| 머신러닝 · ML | 데이터에서 패턴을 배우는 방법 | 과거 판매 기록에서 다음 달 판매량의 패턴 찾기 |
| 딥러닝 · DL | 머신러닝 중 여러 층의 신경망으로 복잡한 패턴을 배우는 방법 | 제품 사진에서 불량의 특징 찾기 |
| LLM · 대규모 언어 모델 | 딥러닝으로 많은 글을 학습해 글을 이해하고 생성하는 모델 | 회의 메모 요약, 메일 문안·코드 작성 |

```text
AI
└─ 머신러닝
   └─ 딥러닝
      └─ LLM
```

안쪽은 바깥쪽에 포함됩니다. Claude 모델이 글을 이해하고 생성하는 역할을 맡고 Claude Code는 그 모델과 파일·실행 도구를 연결해 작업합니다. 오늘은 이미 학습된 모델에 자료를 주고 일을 맡겨 봅니다.

컨텍스트는 이번 일을 이해하는 데 참고하는 정보입니다. 미팅 메모만 주는 경우와 제품 자료·보고 기준까지 함께 주는 경우를 비교해 봅니다.

토큰은 AI가 글을 처리할 때 나누는 조각입니다. 한국어 한 글자나 한 단어와 딱 맞지는 않습니다. 프롬프트와 답변뿐 아니라 읽은 자료와 담당자 작업에도 사용량이 듭니다. 그래서 수업에서는 기준을 미리 파일로 주고 이번에 필요한 자료만 지정합니다. 스킬을 쓴다고 사용량이 없어지는 것은 아닙니다.

## 2. 터미널은 왜 쓰나요?
터미널은 글자로 프로그램을 실행하고 결과를 보는 창입니다. Windows는 PowerShell, macOS는 터미널을 엽니다. pwd는 현재 위치, ls는 목록, mkdir는 폴더 만들기, cd는 이동입니다. 먼저 기본 명령을 보고 바탕화면에 푼 실습 폴더로 이동합니다. Claude Code는 그 창에서 claude로 켜는 프로그램입니다.

## 3. 바이브 코딩과 에이전틱 코딩
이 수업에서는 바이브 코딩을 이렇게 설명합니다. 자연어로 원하는 도구를 설명하고 AI가 만든 결과를 보며 고치는 시작 방법입니다. “숫자가 올라가는 화면을 만들어 줘”로 작은 결과를 볼 수 있습니다. 결과를 읽지 않거나 무조건 믿어야 한다는 뜻으로 사용하지 않습니다.

에이전틱 코딩은 목표를 받은 AI가 계획하고 파일을 읽고 만들고 도구를 실행하고 결과를 검사하며 작업을 이어 가는 방식입니다. 두 말이 서로 떨어진 제품 이름은 아닙니다. 말로 첫 화면을 만든 뒤 기준·검사·재사용까지 갖춰 가는 흐름으로 배웁니다.

## 4. 의도는 기획의 출발점
“영업 보고가 편해졌으면 좋겠다”는 의도입니다. 기획에서는 누구의 어떤 불편인지와 실제 선택을 정합니다. 한빛화학 영업팀이라면 팀장이 결정·제안·할 일을 구분해 보고 싶은지, 어떤 메모를 쓸지, 없는 담당자와 마감은 어떻게 표시할지 정합니다. 사람의 업무 지식을 AI가 읽을 수 있는 기준으로 옮기는 과정입니다.

## 5. 프롬프트와 메타프롬프트
프롬프트는 AI에게 하는 부탁입니다. 작업·자료·결과·확인 기준을 적습니다. 메타프롬프트는 AI에게 프롬프트 작성이나 개선을 맡기는 것입니다. “회의록을 써 줘”에 앞서 “받는 사람과 필수 항목 중 빠진 정보를 질문해 줘”라고 할 수 있습니다. AI의 질문과 제안을 보고 최종 기준은 내가 확인합니다.

## 6. 스펙과 Spec Driven
스펙은 이번에 무엇을 만들고 어떻게 확인할지 적은 약속입니다. Spec Driven은 그 약속을 계획·구현·검사의 기준으로 쓰는 방식입니다. 먼저 아주 작은 카운터를 짧게 부탁해 보고 다음 시연에서 시작 0·클릭 +1·새로고침 0이라는 스펙을 @로 지정합니다. 계획을 확인한 뒤 구현하고 실제 동작을 대조합니다. 상세 설명은 [Spec Driven MD](spec-driven/01_스펙드리븐_쉽게이해하기.md)를 봅니다.

## 7. 공통 규칙, 스킬, 하네스
CLAUDE.md에는 원본을 보존한다 같은 공통 규칙을 적습니다. 스킬에는 한 업무를 반복할 순서·형식·검사 기준을 적습니다. name은 부를 이름이고 description은 무슨 일을 언제 맡기는지 설명합니다. 회의록 스킬을 내 인터뷰 답으로 만들고 다른 회의 메모에 재사용합니다.

하네스는 AI가 일할 자료·도구·규칙·담당자·검사 방법을 준비한 환경입니다. 규칙 파일 하나나 모델 이름 하나와 같지 않습니다. 수업에서는 준비된 계산 도구, 내 규칙, 보고서 스킬, 세 담당자, 결과 확인 방법을 차례로 묶습니다. 별도 제품을 새로 설치하라는 뜻이 아닙니다.

### 에이전트와 서브에이전트
에이전트는 목표를 받고 도구를 쓰며 다음 행동을 고르는 AI입니다. 메인이 전체 보고를 진행하고 자료 확인·보고서 제작·검수처럼 나눈 업무를 서브에이전트에게 맡길 수 있습니다. 서브에이전트는 별도 대화 맥락에서 일하는 AI 담당자입니다. 역할 이름만 세 개 적은 것과 실제로 세 담당자에게 위임한 것은 다릅니다. 수업에서는 호출과 반환 결과를 확인합니다.

### MCP를 Gmail로 이해하기
MCP는 AI와 외부 도구를 연결하는 공통 방식입니다. 보고서 문안을 답변으로 받아 Gmail에 붙여 넣는 대신, 연결된 Gmail의 초안 저장 도구를 Claude가 사용할 수 있습니다. 보고서 작성 절차는 스킬, 초안을 저장할 연결은 MCP입니다. 계정 인증과 지원 도구가 갖춰져야 하며 초안 저장은 발송과 다른 동작입니다.

API는 프로그램끼리 데이터와 결과를 주고받는 창구입니다. MCP 연결 뒤의 도구가 서비스의 API를 이용할 수 있습니다. 여기서는 별도 API 실습을 늘리지 않고 Gmail 초안 하나로 연결의 역할을 봅니다. 로컬 파일 읽기와 터미널 계산 도구도 쓸 수 있으므로 에이전트의 모든 도구가 MCP인 것은 아닙니다.

### 한 업무로 연결해서 기억하기
내 기준과 미팅 메모 → 회의록 스킬과 담당자 → 회의록 → 내 확인 → Gmail MCP로 초안 저장.

스킬은 어떻게 일할지, 서브에이전트는 누구에게 맡길지, MCP는 어떤 외부 도구를 쓸지 정합니다. 하네스는 이 요소들이 함께 일할 환경입니다. 이 문장의 순서를 강사 시연과 연결해 봅니다.

## 8. AI가 일하는 것과 자동화가 도는 것
AI는 보고 형식과 코드 같은 절차를 만드는 데 참여합니다. 완성된 계산 스크립트는 다음 입력에도 같은 계산을 실행할 수 있습니다. 모든 반복 실행마다 모델을 부를 필요는 없습니다. 감시 프로그램이 파일 변경을 알아내고 보고서를 갱신하는 것이 이후 업무 자동화 경험입니다. Gmail MCP는 그 결과 문안을 초안 하나로 옮기는 연결로 배웁니다.

## 11. 시연을 보며 답해 볼 질문
무엇을 입력으로 줬나요? AI가 어떤 파일이나 도구를 다뤘나요? 실제 결과는 어디 있나요? 누가 어떤 기준으로 완료를 확인했나요? 다음 자료에도 같은 절차를 쓸 수 있나요?

말로 답하거나 메모합니다. 이 질문을 추가 모델 프롬프트로 보내지 않습니다.

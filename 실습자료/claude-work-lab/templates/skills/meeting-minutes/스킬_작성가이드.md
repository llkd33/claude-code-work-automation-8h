# 내 기준으로 스킬 쓰기

스킬은 다음에도 같은 방식으로 일하게 저장한 절차입니다. 이번 요청은 프롬프트, 이번 도구의 약속은 스펙, 반복 절차는 스킬에 적습니다. 미팅 메모의 사실과 업무 기준은 서로 다릅니다.

## 왜 인터뷰부터 하나요?
보고받을 사람과 반드시 들어갈 항목은 내가 정합니다. “깔끔하게”보다 “팀장에게 결정·제안·할 일·담당·마감·미정을 구분해 보여 주기”가 확인하기 쉽습니다. 인터뷰는 일반 Claude 대화로 진행하므로 grill-me 설치가 필요하지 않습니다.

## name과 description
name은 /meeting-minutes처럼 직접 부를 이름입니다. 짧은 영문과 하이픈으로 용도를 드러냅니다. description에는 하는 일과 쓰는 상황을 적습니다. “문서를 돕는다” 대신 “영업 미팅 메모를 결정·할 일·미정이 구분된 회의록으로 정리할 때 사용한다”라고 씁니다. 이름과 설명이 구체적이어도 결과가 자동으로 정확해지는 것은 아닙니다.

## description 작성 예시
```yaml
name: meeting-minutes
description: 영업 미팅 메모를 결정·제안·할 일·미정이 구분된 회의록으로 정리할 때 사용한다.
disable-model-invocation: true
```

이 실습은 내가 /meeting-minutes로 부를 때만 실행하도록 true를 둡니다. description은 용도와 사용 상황을 설명합니다. 자동 호출을 허용하는 스킬에서는 Claude가 사용 시점을 판단하는 데에도 이 설명을 참고합니다.

## SKILL.md의 위와 아래
파일 맨 위의 두 --- 사이에는 name·description 같은 설정을 씁니다. 그 아래에는 ## 입력, ## 처리 순서처럼 제목을 붙여 절차를 적습니다. .claude/skills/meeting-minutes/SKILL.md가 실행용 파일이고, 지금 읽는 작성 가이드는 참고자료입니다. 이름 뒤에 .txt가 붙으면 고칩니다. macOS에서 .claude 폴더가 안 보이면 Finder에서 Command+Shift+.를 누릅니다. 편집 후에는 일반 텍스트로 저장합니다.

## 본문에 적을 다섯 가지
입력과 독자, 읽을 자료, 처리 순서, 출력 형식, 확인 기준을 적습니다. 자료를 전부 읽으라고 쓰기보다 사용자가 지정한 회의 메모 한 개부터 읽게 합니다. 없는 담당자를 채우지 않기, 제안을 확정 수주로 바꾸지 않기 같은 기준도 남깁니다.

## 만들고 사용하기
빈칸 양식을 참고해 일반 대화로 인터뷰를 요청합니다. 한 질문씩 답하고 요약을 확인하면 Claude가 파일을 저장합니다. 텍스트 편집기로 name·description·본문을 확인하고 내 답이 빠진 곳은 직접 고칩니다. 같은 폴더에서 Claude를 다시 켜 /meeting-minutes를 호출합니다. 외부 미팅 다음에는 내부 회의로 입력만 바꿔 재사용합니다.

## 원문과 대조하기
결정과 제안이 구분됐는지, 담당과 기한이 원문에 있는지, 미정이 남았는지 확인합니다. 사실을 고쳐 쓰는 대신, 어떤 정보를 놓쳤는지 절차를 보강합니다. 스킬은 행동 지침이며 실행 권한이나 사실 검증을 대신하지 않습니다.

## 두 번째 예시: 주간 비용 보고서
weekly-report는 제공된 숫자 계산·검사·출력 절차를 쓰는 스킬입니다. 호출 이름과 실행 명령은 유지하고 description의 사용 상황과 확인 기준을 고쳐 봅니다. 회의 메모의 제안액을 비용 합계나 확정 매출로 섞지 않습니다.

# 비개발자 Claude Code 8H 과정 리뷰와 업데이트 제안

검토일: 2026-10-08. 대상: 현행 `강의기획서.md`, `교안.md`, `사전준비.md`, 학생 실습기록, Google MCP 안내, 팀 Skill, 보고서 완성본, 최신 제작·검증 기록. 기준은 **쉽게 시작해서, 직접 확인한 결과물을 만들고, 다음 업무에도 다시 쓰는가**이다. 이 문서는 개편 제안이며 현행 교안·배포본에 적용한 결과가 아니다.

핵심 판단: 현재 자료는 숫자 대조·원본 보존·복구·실연동과 모의 구분이 잘 되어 있다. 그러나 하루에 학습하는 환경과 기능이 많고, 핵심 결과물의 완성이 Google 인증·변환에 의존한다. **한 업무를 완성하는 공통 경로를 먼저 확보하고, Skill·새 입력 검증·동료 재실행을 강화**하면 쉽게 따라가면서도 결과가 남는 과정이 될 가능성이 높다. 효과는 초보자 리허설에서 확인해야 한다.

GUI 경로는 교육장 OS·계정·현재 MCP 설정이 같은 흐름으로 동작하는지 확인한 뒤 채택해야 한다.

## 2. 이미 좋은 부분 — 그대로 살릴 것

- **하나의 비용 업무를 이어가는 구조:** 가상 Excel 40건을 M2에서 가져오고 같은 Sheets를 M3에서도 사용한다. 과거 CSV 중심 버전으로 되돌려 평가하지 않는다.
- **숫자로 결과를 확인:** 40건·2,333,300원 → E003 수정 후 2,338,300원 → E041 추가 후 41건·2,363,300원으로 확인 지점이 구체적이다.
- **사람이 요구를 정함:** IA·여정·PRD 10칸 작성, 기능 최대 3개, 완료 기준을 학생이 고르는 구조가 있다. 이 요구를 유지하면서 첫 성공과 배치 순서를 조정한다.
- **복구와 비용 관리:** 원본 보존, 특정 ID의 행을 찾아 수정, 재조회, 마지막 정상 결과 보존, 반복 계산의 코드 재사용을 이미 가르친다.
- **검증 한계를 구분:** 모의 성공·실제 Google 성공·예약 설치·다음 날 실행을 혼동하지 않는다. 이는 계속 유지할 강점이다.

## 4. 추천 수료 결과 — 가져갈 결과를 한 묶음으로

공통 최종 결과는 **‘매주 쓰는 비용 마감 도구’**로 통일한다. 오전 체크리스트와 오후 보고서를 같은 업무 폴더에 묶는다. 개인 업무는 기존 비용표의 데이터·규칙·보고서 표현 중 하나를 바꾸는 수준부터 시작한다.

| 반드시 가져갈 것 | 학생이 확인할 기준 |
| --- | --- |
| 보고서 HTML 1개 + 공유용 요약 문안 | 직접 열 수 있음, 날짜·출처·핵심 숫자·확인할 일이 있음. 사실 계산과 AI 의견을 구분 |
| 다시 실행할 도구와 실행 카드 | 입력을 바꾸는 위치와 실행 순서가 있음. 최신 입력 읽기와 저장된 결과 재생성을 구분 |
| 본인 업무 Skill 1개 + 짧은 CLAUDE.md | Skill은 반복 작업 절차, CLAUDE.md는 프로젝트 공통 규칙. 같은 규칙을 길게 중복하지 않음 |
| 실제 확인 기록 | 정상·같은 입력 재실행·새 입력·오류 입력 결과와 실행 경로 표시 |
| 본인이 고친 업무 기준 1개 | 학생이 선택한 기준이 출력에서 확인됨. 예: 진행 항목만 요약, 특정 부서 강조, 금액 기준 초과 표시 |

결과 파일의 수보다 **내가 만든 결과를 설명하고 다시 쓸 수 있는지**를 본다. Google 실연동·외부 API·3명 팀·자동 예약은 각자 별도 확장 기록을 남긴다.

## 6. 쉬워지면서도 에이전틱한 핵심 실습

학생은 아래 4칸을 먼저 자기 말로 작성한다. JSON·셀 좌표·OAuth 설정은 강사와 준비 템플릿이 맡고, 학생은 입력과 업무 기준을 고른다.

```text
할 일: 매주 비용표에서 부서별 금액과 미처리 항목을 정리한다.
재료: 제공한 비용표 사본과 내가 정한 마감 기준.
결과 예시: 총액·부서별 금액·확인할 일 3개가 있는 보고서와 공유 문안.
확인 기준: 원본 보존, 합계 대조, 날짜·출처 표시, 금액 누락 시 중단.
```

강사는 학생 입력과 별도로 실행 계약을 붙인다. ‘알아서 자동화해’로 모든 결정을 맡기지 않는다.

```text
먼저 지정 입력의 구조와 필수 항목을 확인해줘.
애매한 기준은 결과를 바꿀 질문 2개까지만 물어봐.
검증한 처리기로 계산·결과 생성을 실행하고, 실제 파일을 저장해줘.
보고서는 숫자와 출처를 대조하고, 직접 확인하지 못한 항목은 미확인으로 남겨.
기준이 맞지 않으면 그 문제만 1회 수정하고 다시 확인해.
두 번 실패하면 마지막 정상 결과를 보존하고 오류를 기록한 뒤 멈춰.
끝나면 입력·실행 순서·결과·검사 결과·다음 행동을 짧게 남겨.
```

여기서 에이전틱한 경험은 필요한 정보를 읽고, 정한 기준에 따라 실행하고, 오류를 발견하면 제한 안에서 수정하며, 결과와 상태를 남기는 과정이다. 반복 계산은 검증된 코드에 맡긴다. Skill로 호출할 때 AI 판단·도구 호출은 사용량을 쓰고, LLM 없는 계산 코드의 직접 실행은 모델 토큰을 쓰지 않는다는 기존 설명을 유지한다.

## 8. 파일럿에서 측정할 것

이 수치는 결과 약속이 아니라 다음 개편을 비교하기 위한 **제안 목표**이다. 비교 가능한 비개발자 3–5명으로 첫 리허설을 하고 인원이 작다는 한계를 기록한다.

| 지표 | 제안 목표·기록 방법 |
| --- | --- |
| 첫 성공까지 시간 | 환경 준비 완료 학생이 60분 내 실제 파일을 만들고 열기. 미준비 학생 지원시간 별도 |
| 필수 결과 확보 | 운영 개선 목표 80% 이상. 소수 파일럿은 비율만 쓰지 말고 4/5처럼 인원 병기 |
| 새 입력 재실행 | 해당 학생이 실행 카드로 10분 내 성공하거나, 명확한 오류를 발견하고 멈춤 |
| 정확성 | 제출 결과의 필수 합계·출처 검사 전부 통과. 새 입력 실패를 결과 완성으로 인정하지 않음 |
| 자율 수정 | 전체 프롬프트 복사 없이 업무 기준 한 가지를 바꾸고 출력에서 확인 |
| 지원 의존도 | 학생별 도움 횟수·대기시간·막힌 단계 기록. 운영 인력 요구를 숨기지 않음 |
| 사용량·비용 | 계정 방식에 맞는 사용량 화면 또는 API 청구 기준 기록. 프롬프트 개수로 비용을 대체하지 않음 |
| 수업 이후 재사용 | 7일 뒤 같은 절차를 새 입력으로 다시 실행한 인원·검사 결과 확인. 후속 연락은 운영진 계획으로 두고 이번 리뷰에서 발송하지 않음 |

수료 확인은 결과 파일, 새 입력 실행 기록, 본인 기준 수정, 실행 카드, 미확인 항목의 구분으로 한다. 자동 예약은 당일 수동 성공이나 설치 목록만으로 ‘다음 날 자동 실행 성공’이라고 평가하지 않는다.

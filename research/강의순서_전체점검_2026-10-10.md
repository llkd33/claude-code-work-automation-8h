# 강의 순서 전체 점검 · 2026-10-10

대상은 비개발자 개인 실습, Claude Code in Terminal 과정입니다. 실제 본문·입출력 계약·독립 구조 검수로 순서를 점검했습니다. 초보자 완주 관찰 결과는 아닙니다.

| 발견한 문제 | 바꾼 순서와 이유 |
| --- | --- |
| Excel을 열었다가 체크리스트를 만들고 다시 Excel로 복귀 | 첫 작품과 인터뷰·검사를 연속으로 끝낸 뒤 비용 업무로 전환 |
| 규칙과 Skill을 익히기 전에 팀 구축 | 정상·오류·복구 → 내 기준 → 규칙 → Skill → 팀으로 연결 |
| 실행기 제작·실행·검사를 마무리에 몰아넣음 | 다음 주 보고서 직후 같은 입력으로 실행기를 만들고, 이후 자동화·시연으로 연결 |
| 터미널을 사용하는 시연 다음에 터미널 설명 | 결과 미리보기 다음에 터미널 역할과 화면부터 준비 |
| 오전에 여러 기능 이름을 한꺼번에 설명 | 입력·결과·검사부터 이해하고 용어는 실제 사용할 때 설명 |
| 다음 주 입력 뒤 앱에서 원본 샘플로 되돌아감 | 앱은 다음 주 12건 사본을 이어 사용. 감시의 원본 → 다음 주 전환은 명시 |
| 문서마다 다른 배분과 오래된 지침 | 단일 진행 순서로 재작성하고 시각·분 단위 배분 삭제 |
| 요청 번호와 호출 순서가 뒤집힘 | A4 Skill → A5 팀 → A6 다음 주로 정렬 |

현재 흐름: **첫 작품 → 비용 보고서·검사 → 내 기준·CLAUDE.md·Skill → 3명 팀·다음 주 → 로그인 실행기·파일 변경 자동화**.

| 혼자 재실행·시연·제출 | 작품과 실행 카드, 통과·미확인 기록 | 다음 업무에 적용할 방법 |

각 단계에서 만들 결과·확인 기준·다음에 쓸 파일을 안내합니다. 정규 3명 팀, /grill-me 설치·인터뷰, Skill name·description·예시, 로그인 기반 실행기, 개인 실습을 유지합니다. API 키는 필요하지 않습니다. Gmail 초안은 선택, Playwright는 후반 소개입니다.

독립 검수는 선수학습 구조를 확인했습니다. 검수 뒤 분 단위 안내를 제거했으므로 해당 변경은 공개 자료 검사로 별도 확인합니다. 실제 재미·몰입·완주 여부는 수강생 리허설로 확인할 항목입니다. 과거 스냅샷과 원 배분 기록은 공개 교안과 분리해 보존합니다.

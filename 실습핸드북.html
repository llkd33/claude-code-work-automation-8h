모델과 Effort · 누구에게 맡기고 얼마나 생각하게 할까?

모델은 일을 맡는 AI의 종류입니다. 화면의 선택지는 업데이트되므로 특정 번호를 외우기보다, 쉬운 일에는 빠르고 가벼운 모델, 복잡한 분석·코딩에는 성능이 높은 모델을 고릅니다. 비용·속도·품질의 균형이 달라질 수 있습니다.

Effort(생각의 깊이)는 선택한 모델이 어려운 일을 얼마나 깊게 따져볼지 정하는 설정입니다. 메뉴에 표시되는 수준과 지원 여부는 모델마다 다를 수 있습니다. 쉬운 문장 정리는 낮게, 여러 파일을 살피고 원인을 찾는 일은 높게 두면 됩니다. Effort가 높다고 사실이 자동으로 맞아지는 것은 아니므로 결과 확인은 계속 필요합니다.

모델은 ‘누가 맡을지’, Effort는 ‘얼마나 꼼꼼히 생각할지’입니다. 이름과 단계는 서비스 업데이트에 따라 바뀔 수 있습니다.

Claude 채팅과 Claude Code · 참고 자료의 범위가 다릅니다

Claude 채팅은 대화창에 적거나 첨부한 자료를 중심으로 답합니다. 프로젝트 기능을 쓰면 공통 지침과 자료를 참고할 수 있지만, 각 대화의 내용이 자동으로 서로 공유되는 것은 아닙니다.

Claude Code는 먼저 지정한 실습 폴더를 작업 공간으로 삼습니다. 허용된 범위 안에서 파일을 찾아 읽고, 만들고, 명령을 실행하며 결과를 확인할 수 있습니다. 프로젝트의 CLAUDE.md는 반복 규칙, 현재 대화는 지금 할 일, Excel·메모 파일은 실제 자료라고 생각하면 됩니다.

채팅과 Code가 항상 서로 다른 크기의 컨텍스트를 쓰는 것은 아닙니다. 한 번에 참고할 수 있는 양은 모델·플랜·환경에 따라 달라집니다. Code에서는 대화뿐 아니라 읽은 파일과 실행 결과도 참고 범위에 들어오므로, 필요 없는 파일을 많이 읽히면 중요한 맥락이 묻히고 사용량도 늘 수 있습니다. 채팅의 프로젝트 자료도 프로젝트 지식으로 올린 파일은 다른 대화에 참고될 수 있지만, 대화 내용 자체가 자동 공유되지는 않습니다. 그래서 색인으로 필요한 파일부터 고릅니다. 고객 개인정보·비밀번호·API 키는 실습 자료에 넣지 않습니다.

HTML · Markdown · JSON · HTML은 웹 화면, Markdown(.md)은 글 문서, JSON은 항목과 값을 짝지은 데이터입니다. 예: “건수: 41”.

02. 터미널이 하는 일과 화면 준비

이번에 할 일 PowerShell/터미널을 열고 실습 폴더로 이동합니다.

개념 터미널은 글자로 프로그램을 켜는 창입니다. 이곳에서 Claude Code를 켜면 한국어로 파일 작업을 부탁할 수 있습니다.

Claude Code를 여는 세 가지 화면

Terminal · PowerShell

장점 설치·로그인부터 파일 작업까지 한곳에서 진행합니다. Windows와 Mac에서 순서가 거의 같습니다.

아쉬운 점 검은 창과 몇 가지 짧은 명령이 처음엔 낯섭니다.

VS Code

장점 파일과 대화를 한 화면에 두고, 바뀐 내용을 비교하며 확인하기 편합니다.

아쉬운 점 VS Code와 Claude Code 확장 설치가 필요하고, 버튼과 패널이 더 많습니다.

Claude Desktop · Code 탭

장점 프로젝트를 고르고, 대화·파일 변경·웹 미리보기를 화면에서 살펴보기 쉽습니다.

아쉬운 점 앱과 작업 폴더를 먼저 골라야 하며, 자동화용 터미널 기능은 제한됩니다.

이 수업에서 터미널을 쓰는 이유

수업 자료가 Windows PowerShell과 Mac 터미널에서 같은 순서로 열리도록 준비되어 있습니다. 폴더를 직접 선택하고 claude를 켠 다음, 파일 작업은 쉬운 한국어로 시킵니다. 터미널 명령을 많이 외우는 수업은 아닙니다.

개념 에이전틱 코딩 · 실행까지 맡기기

이 에이전트 방식으로 코드와 업무 도구를 만들고 고치는 것이 에이전틱 코딩입니다. AI가 계획 → 파일 작업 → 실행 → 확인을 이어가고, 나는 원하는 결과를 정하고 직접 써 봅니다.

예: “체크리스트를 만들고, 추가·완료·새로고침이 되는지 확인해줘.”

모드와 권한

  • Plan: 먼저 계획을 봅니다. 큰 변경이나 처음 하는 작업에 씁니다.
  • Manual · 수동: 작업하며 필요한 권한을 묻습니다.
  • Edit automatically · 편집 허용: 파일 편집을 자동으로 허용합니다. 명령 실행에는 별도 확인이 필요할 수 있습니다.
  • Auto: 작업의 안전성을 자동으로 확인하고, 위험한 행동은 멈춰 확인받습니다.

Shift + Tab으로 모드를 바꿉니다. 사용 가능한 모드는 설치 버전과 계정에 따라 다를 수 있습니다. 모드 안내

처음 만들 때: Manual(수동)에서 시작해 권한 창을 읽어 봅니다. Plan에서 계획을 확인했다면, 승인 화면에서 편집을 허용해 만들기를 시작합니다.

권한 창에서는 대상 파일과 할 일을 읽습니다. 실습 폴더에 결과를 만드는 작업은 확인 후 허용하고, 원본 삭제나 메일 발송은 거절합니다.

배경을 연한 초록색으로 바꾸고 제목은 ‘천천히 하나씩’으로 해줘. 숫자 세기는 그대로 둬.
  1. 수정된 화면을 브라우저에서 엽니다.
  2. 고른 미션이 보이거나 동작하는지 확인하고, 버튼을 눌러 숫자가 1씩 올라가는지도 봅니다.
  3. 원하는 모습과 다르면 마음에 안 드는 부분 하나만 다시 말합니다. 새로고침 후 숫자가 0으로 돌아와도 저장 기능을 따로 넣지 않았다면 정상입니다.

‘하나만 바꾸기 → 직접 눌러 보기 → 한 번 더 다듬기’가 첫 작품을 만드는 기본 리듬입니다.

P125 · Claude Code 안 · 고객관리 앱 인터뷰
나는 B2B IT SaaS를 세일즈하고 있어. 고객 정보와 미팅 내용이 수첩·이메일·카카오톡에 흩어져 있어 후속 연락을 놓치거나 상담 맥락을 다시 찾기 어려워. 이 문제를 해결할 고객관리 도구를 설계하고 싶어.
실제 고객 정보는 쓰지 말고, 먼저 내 업무에서 불편한 순간과 필요한 결과를 한 번에 하나씩 물어봐 줘. 이미 말한 내용은 다시 묻지 말고, 필요한 질문은 최대 5개로 해줘.
인터뷰 후 해결할 문제와 사용자를 쉬운 말로 요약해 확인받아. 내가 확인하면 IA 초안(화면에 어떤 정보를 어떻게 모을지)을 보여주고 승인받아.
IA를 승인한 뒤에만 User Journey(언제 열어 무엇을 하고 어떤 결과를 얻는지)를 만들고 다시 승인받아. 그다음 PRD(만들 목표, 필요한 기능, 완료 기준)를 작성해 확인받아. 매 단계에서 모르는 내용은 추측하지 말고 물어봐 줘.
최종 도구는 로컬 전용으로, 인터넷 서버·클라우드·로그인·외부 연동 없이 이 PC의 브라우저에서만 쓰게 해줘. 데이터는 같은 브라우저에 저장하고 가상 자료만 사용해. IA·User Journey·PRD를 차례로 승인받기 전에는 코드를 만들지 말고, PRD까지 승인받은 뒤에만 한 화면의 작은 웹앱을 만들어 새로고침 뒤에도 기록이 남는지 확인해줘.

인터뷰 → IA → User Journey → PRD → 앱 제작 순서로 진행합니다. 각 문서를 확인하고 승인한 뒤 다음 단계로 넘어갑니다. 로컬 저장은 같은 브라우저·기기에서만 이어지고, 다른 사람과 자동 공유되지 않습니다.

제작 사례 영업 딜 관리 도구를 브라우저에서 확인하기

실제 사례에서는 기획을 마친 뒤 Vite 프로젝트 폴더에서 Claude Code를 열고 개발 서버를 실행해 화면을 확인했습니다. 처음 폴더를 열 때 신뢰 여부를 묻는 화면이 나오면 내가 만들었거나 신뢰하는 폴더인지 확인한 뒤 진행합니다. 아래 명령은 package.json에 개발 서버 실행 방법이 준비된 프로젝트에서만 씁니다.

  1. 실습 프로젝트 폴더에서 Claude Code를 엽니다.
  2. 터미널에 npm run dev를 입력합니다. 이 프로젝트는 화면과 서버를 함께 켰습니다. 화면 주소는 http://localhost:5173, 서버 주소는 http://localhost:5174였습니다. localhost는 내 컴퓨터에서 여는 주소입니다.
  3. Claude Code에 자연어로 수정할 점을 하나씩 말합니다. 화면 파일이 바뀌면 브라우저가 자동으로 갱신되므로 결과를 보고 다음 프롬프트를 정합니다.
  4. 완성한 파일은 output/deal-tracker/index.html이었고, 영업 딜 관리 화면에 가상 거래 9건이 들어 있었습니다. 보고서 복사와 JSON 내보내기를 직접 눌러 확인합니다. 당시 제작 기록에서는 이 두 기능을 끝까지 검증하지 않았으므로 성공을 가정하지 않습니다.

실습 흐름: 프로젝트 폴더 열기 → 서버 켜기 → 화면 보기 → 한 가지씩 수정 → 직접 눌러 확인하기. 실제 고객 정보 대신 가상 자료를 사용합니다. localhost에서 화면이 열린다는 사실만으로 앱이 완전히 오프라인이거나 AI 통신도 로컬이라고 단정할 수는 없습니다.

# 내 도구를 정하는 짧은 인터뷰 · 교육용

Matt Pocock의 grill-me/grilling에서 질문으로 계획을 구체화하는 방식을 참고한 수업용 버전이다. 원본과 달리 다른 스킬 없이 실행하며, 8H 개인 실습 범위에서 인터뷰를 끝낸다.

사용자의 프롬프트: $ARGUMENTS

## 질문과 종료

- 한국어로 쉬운 질문을 한 번에 하나씩 하고 답을 기다린다. 이미 알려 준 내용은 다시 묻지 않는다. 최대 3개 질문으로 필요한 내용을 정한다.
- 누가 언제 쓰는지, 남기고 싶은 정보와 입력 방법, 보고 싶은 결과와 추가 기능을 답에서 구체화한다. 장소 이름은 예시이며 특정 항목이나 앱으로 제한하지 않는다.
- 질문에는 추천 선택지와 자유롭게 답할 여지를 준다. 최종 선택은 사용자가 한다. 기능은 최대 3개, 화면은 1개로 줄이고 나머지는 다음 개선으로 남긴다.
- 이 실습은 HTML 한 파일, 외부 라이브러리·API·서버·로그인 없는 범위다. 범위를 넘는 기능은 구현 가능한 작은 대안을 함께 제안하고 선택을 기다린다.
- 사용 동작으로 확인할 기준을 정한다. 예: 두 건 입력 → 한 건 완료 → 새로고침 후 저장 확인. 실행하지 않은 검사는 미확인이다.
- 질문 뒤 확정한 내용과 남은 선택을 요약하고 사용자 확인을 기다린다. 3개 질문 뒤에도 중요한 선택이 남으면 추측하지 말고 그 선택을 표시한다. 사용자가 더 묻기를 원하면 추가 질문 횟수를 기록한다.

## 확인 후 남길 두 파일

사용자가 계획을 확인하면 다음 파일만 작성한다. 아직 앱을 구현하지 않는다. 같은 이름이 있으면 보존하고 새 파일명을 안내한다.

1. `notes/내도구_인터뷰.md`: 사용자 답, 확정 기능, 다음 개선, 직접 검사 기준. `templates/planning/01_내도구_빈칸템플릿.md`의 PRD 4칸·IA 3칸·사용 여정 3칸에 맞춰 확인한 계획을 정리한다. 모르는 내용은 미정으로 표시한다.
2. `notes/내도구_구현요청.txt`: 그 계획을 포함한 복사 가능한 구현 프롬프트. 기존 파일 보존과 새 HTML 파일명 안내, 기능 최대 3개·화면 1개, 브라우저 localStorage 저장과 저장 실패 안내, 입력 텍스트를 HTML로 실행하지 않기, 실제 검사와 미확인 구분을 포함한다. 계획은 사용자가 확인했다는 표현을 쓴다.

끝에는 실제 파일명과 남은 선택만 짧게 안내한다. 사용자가 내용을 읽고 구현 프롬프트를 따로 붙여 넣어야 구현을 시작한다.

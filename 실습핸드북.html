  4. 잘못됐을 때 다시 부탁하기 · 결과가 이상할 때

05. 에이전트부터 에이전틱 코딩까지

이번에 할 일 AI가 하는 일과 내가 확인할 일을 구분합니다.

개념 에이전트 · 목표를 주면 방법을 정하고 일하는 AI

AI에게 목표를 주면, 필요한 일을 나누고 허용된 도구로 작업한 뒤 결과를 확인합니다. 이런 방식으로 일하는 AI를 에이전트라고 부릅니다. 내가 원하는 결과와 맡길 범위를 먼저 알려 줍니다. 공식 설명

① 내가 목표 정하기“숫자 버튼을 만들어줘.”
② AI가 작업하기계획 → 파일 만들기 → 동작 확인
③ 내가 결과 보기브라우저에서 버튼을 눌러 보기

업무에서도 같습니다. “이 회의 메모를 팀장용 회의록으로 정리해줘”라고 맡기면 메모를 읽고, 결정과 할 일을 정리하고, 파일로 저장하게 할 수 있습니다. 모르는 담당자나 날짜는 내가 알려 줍니다.

Claude·Cowork·Claude Code · 차이가 궁금하면

Claude는 AI와 서비스의 이름입니다. 아래는 같은 AI를 어떤 방식으로 쓸지 비교한 예시입니다.

이름주로 맡길 일회의 메모로 예를 들면
Claude 일반 대화질문·아이디어·문장 다듬기“이 메모에서 중요한 내용이 뭐야?”
Claude Cowork파일과 연결 도구를 써서 업무 결과물 만들기“이 메모들을 읽고 회의록 파일로 정리해줘.”
Claude Code파일·코드·명령을 다뤄 도구를 만들고 반복 실행하기“메모를 넣으면 같은 양식의 회의록을 만드는 도구를 만들어줘.”

일반 대화에서도 파일을 만들 수 있습니다. 일부 계정은 Chat과 Cowork가 한 대화 화면으로 통합되어 보입니다. 이름보다 무엇을 맡기고 어떤 결과를 받을지로 고르면 됩니다. Claude·Cowork 공식 안내

이번 수업은 터미널에서 Claude Code를 사용합니다. 한국어로 부탁하면 실습 폴더에 파일을 만들고 명령을 실행하며, 내가 다시 쓸 업무 도구를 만들어 봅니다. Claude Code 공식 안내

개념 에이전틱 코딩 · 실행까지 맡기기

이 에이전트 방식으로 코드와 업무 도구를 만들고 고치는 것이 에이전틱 코딩입니다. AI가 계획 → 파일 작업 → 실행 → 확인을 이어가고, 나는 원하는 결과를 정하고 직접 써 봅니다.

예: “체크리스트를 만들고, 추가·완료·새로고침이 되는지 확인해줘.”

모드와 권한

  • Plan: 먼저 계획을 봅니다. 큰 변경이나 처음 하는 작업에 씁니다.
  • Manual · 수동: 작업하며 필요한 권한을 묻습니다.
  • Edit automatically · 편집 허용: 파일 편집을 자동으로 허용합니다. 명령 실행에는 별도 확인이 필요할 수 있습니다.
  • Auto: 작업의 안전성을 자동으로 확인하고, 위험한 행동은 멈춰 확인받습니다.

Shift + Tab으로 모드를 바꿉니다. 사용 가능한 모드는 설치 버전과 계정에 따라 다를 수 있습니다. 모드 안내

처음 만들 때: Manual(수동)에서 시작해 권한 창을 읽어 봅니다. Plan에서 계획을 확인했다면, 승인 화면에서 편집을 허용해 만들기를 시작합니다.

권한 창에서는 대상 파일과 할 일을 읽습니다. 실습 폴더에 결과를 만드는 작업은 확인 후 허용하고, 원본 삭제나 메일 발송은 거절합니다.

# 내 도구를 정하는 짧은 인터뷰 · 교육용

Matt Pocock의 grill-me/grilling에서 질문으로 계획을 구체화하는 방식을 참고한 수업용 버전이다. 원본과 달리 다른 스킬 없이 실행하며, 8H 개인 실습 범위에서 인터뷰를 끝낸다.

사용자의 프롬프트: $ARGUMENTS

## 질문과 종료

- 한국어로 쉬운 질문을 한 번에 하나씩 하고 답을 기다린다. 이미 알려 준 내용은 다시 묻지 않는다. 최대 3개 질문으로 필요한 내용을 정한다.
- 누가 언제 쓰는지, 남기고 싶은 정보와 입력 방법, 보고 싶은 결과와 추가 기능을 답에서 구체화한다. 장소 이름은 예시이며 특정 항목이나 앱으로 제한하지 않는다.
- 질문에는 추천 선택지와 자유롭게 답할 여지를 준다. 최종 선택은 사용자가 한다. 기능은 최대 3개, 화면은 1개로 줄이고 나머지는 다음 개선으로 남긴다.
- 이 실습은 HTML 한 파일, 외부 라이브러리·API·서버·로그인 없는 범위다. 범위를 넘는 기능은 구현 가능한 작은 대안을 함께 제안하고 선택을 기다린다.
- 사용 동작으로 확인할 기준을 정한다. 예: 두 건 입력 → 한 건 완료 → 새로고침 후 저장 확인. 실행하지 않은 검사는 미확인이다.
- 질문 뒤 확정한 내용과 남은 선택을 요약하고 사용자 확인을 기다린다. 3개 질문 뒤에도 중요한 선택이 남으면 추측하지 말고 그 선택을 표시한다. 사용자가 더 묻기를 원하면 추가 질문 횟수를 기록한다.

## 확인 후 남길 두 파일

사용자가 계획을 확인하면 다음 파일만 작성한다. 아직 앱을 구현하지 않는다. 같은 이름이 있으면 보존하고 새 파일명을 안내한다.

1. `notes/내도구_인터뷰.md`: 사용자 답, 확정 기능, 다음 개선, 직접 검사 기준. `templates/planning/01_내도구_빈칸템플릿.md`의 PRD 4칸·IA 3칸·사용 여정 3칸에 맞춰 확인한 계획을 정리한다. 모르는 내용은 미정으로 표시한다.
2. `notes/내도구_구현요청.txt`: 그 계획을 포함한 복사 가능한 구현 프롬프트. 기존 파일 보존과 새 HTML 파일명 안내, 기능 최대 3개·화면 1개, 브라우저 localStorage 저장과 저장 실패 안내, 입력 텍스트를 HTML로 실행하지 않기, 실제 검사와 미확인 구분을 포함한다. 계획은 사용자가 확인했다는 표현을 쓴다.

끝에는 실제 파일명과 남은 선택만 짧게 안내한다. 사용자가 내용을 읽고 구현 프롬프트를 따로 붙여 넣어야 구현을 시작한다.

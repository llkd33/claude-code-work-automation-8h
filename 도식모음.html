D01 오늘 만드는 결과를 한눈에 보기

그림 확대핸드북의 해당 실습

그림을 글로 읽기

  1. 오전 설명·시연 뒤 오후에 체크리스트와 회의록 스킬을 만들고 Excel 보고서의 숫자와 오류를 확인합니다.
  2. CLAUDE.md와 Skill로 절차를 남긴 뒤 세 담당자에게 위임하고 새 입력에 재사용합니다.
  3. 같은 비용 업무를 로그인 실행 버튼과 파일 변경 감시로 실행합니다.
  4. 개인 실습이며 A1–A8와 스킬 인터뷰 요청을 구분합니다. 오전 3H는 설명·강사 시연, 오후 5H는 개인 실습입니다.

D02 어디에 입력할지 먼저 구분하기

그림 확대핸드북의 해당 실습

그림을 글로 읽기

  1. 터미널에서 claude를 실행한 뒤 Claude Code의 입력란에 목표와 제작 요청을 입력합니다. A8은 앱이 내부에서 보냅니다.
  2. node 명령은 셸이 열린 실행 창에서 실행합니다. Claude Code가 실행 중인 입력란과 구분합니다.
  3. 편집기에서는 파일의 규칙과 계획을 수정합니다. 브라우저에서는 실제 결과의 숫자와 동작을 확인합니다.

D03 원본에서 내 결과까지의 흐름

그림 확대핸드북의 해당 실습

그림을 글로 읽기

  1. workbooks 폴더의 제공 원본은 보존하고 내주간비용.xlsx 사본만 수정합니다.
  2. 검증된 local-report 도구를 실행하면 report.html, summary.json, share.txt, verification.json이 만들어집니다.
  3. 내 사본 결과는 output/my-costs입니다. 공통 제공 수정후 파일 결과는 output/local-final이며 3명 팀이 읽습니다. 같은 숫자를 보고서와 팀에서 사용합니다.

D04 한 건 수정하고 한 건 추가하기

그림 확대핸드북의 해당 실습

그림을 글로 읽기

  1. 원본은 40건, 2,333,300원입니다.
  2. E003의 단가를 10,000원에서 15,000원으로 바꾸고 진행을 완료로 바꾸면 40건, 2,338,300원입니다. 총액이 5,000원 늘어납니다.
  3. E041을 수량 1, 단가 25,000원으로 추가하면 41건, 2,363,300원입니다. 총액이 다시 25,000원 늘어납니다.
  4. 다음주 파일 12건, 1,130,900원은 별도의 새 입력입니다.

D05 MCP는 Gmail 초안 한 개로 경험하기

그림 확대핸드북의 해당 실습

그림을 글로 읽기

  1. 교육용 Gmail을 연결하고 같은 Claude 계정의 Terminal에서 /mcp로 실제 도구를 확인합니다.
  2. 보고서 share.txt와 교육용 수신자로 초안 한 개만 저장합니다. 메일함 전체 검색과 발송은 하지 않습니다.
  3. 실제 도구 응답의 초안 ID와 Gmail 임시보관함을 확인합니다. 저장 도구가 없으면 미완료로 끝냅니다.

D06 오류 뒤에는 검사 결과부터 읽기

그림 확대핸드북의 해당 실습

그림을 글로 읽기

  1. 입력이 실패하면 마지막 정상 report.html, summary.json, share.txt 세 파일은 보존됩니다.
  2. 이번 verification.json의 ok: false와 오류 내용을 읽고 입력을 수정합니다.
  3. 같은 도구를 다시 실행하고 ok: true를 확인한 뒤 최신 결과를 사용합니다. 파일 존재만으로 새 성공을 판단하지 않습니다.

D07 규칙·절차·계산·데이터의 역할

그림 확대핸드북의 해당 실습

그림을 글로 읽기

  1. CLAUDE.md는 공통 규칙이고 SKILL.md는 한 업무의 실행과 검사 절차입니다.
  2. weekly-report.cjs가 실제 계산을 수행하고 .xlsx는 이번 입력 데이터입니다.
  3. Claude Code가 규칙과 Skill을 참고해 도구를 실행하더라도 Skill 파일이 있는 것만으로 실제 Skill 호출을 증명하지는 않습니다.
  4. CLAUDE.md를 작성하는 것은 runtime 상담봇 모델을 훈련시키는 일이 아닙니다.

D08 watch가 반복 확인하는 순서

그림 확대핸드북의 해당 실습

그림을 글로 읽기

  1. 첫 입력이거나 파일 바이트가 바뀌면 입력을 검사합니다. 마지막 성공 입력과 같으면 skipped로 건너뜁니다.
  2. 정상 입력은 보고서를 생성하고 성공 파일 지문을 저장합니다. 오류 입력은 정상 세 파일을 보존하고 성공 지문을 저장하지 않으며 다음 검사에서 재시도합니다.
  3. 5초 간격 최대 12회이며 계산 시간이 추가될 수 있습니다. 60초 이후 새 검사는 시작하지 않고 진행 중인 검사는 마칩니다. Ctrl+C로도 중단합니다.
  4. 노트북과 터미널이 켜져 있어야 합니다. 셀 값이 아닌 파일 바이트를 비교하므로 글꼴 변경도 파일 변경이면 감지합니다.

D09 Claude가 켜고 파일만 바꿔 보기

그림 확대핸드북의 해당 실습

그림을 글로 읽기

  1. Claude 안에 시작 요청을 붙입니다. 별도 실행 창에서 로그를 보고, 탐색기에서 입력 사본을 교체합니다.
  2. 기본 원본 40건에서 시작한 뒤 탐색기에서 다음 주 파일을 넣고 실행 창의 generated와 12건을 확인합니다. 브라우저를 수동 새로고침한 뒤 skipped를 봅니다.
  3. 오류 실습은 watch를 따로 재시작합니다. 오류 파일 사본을 넣고 error 로그를 기다린 뒤 다음 주 정상 파일로 바꿉니다.
  4. 복구 generated와 ok: true를 확인한 뒤 Ctrl+C 또는 횟수 종료로 마칩니다. 파일 교체 사이에 해당 로그를 기다립니다.

D10 텍스트를 내려받아 내 요청으로 바꾸기

그림 확대핸드북의 해당 실습

그림을 글로 읽기

  1. 수강생_통합자료.zip을 한 번 내려받아 풀고, 오늘 쓸 프롬프트 파일을 엽니다.
  2. 프롬프트는 목적을 확인하고 필요한 자료를 참고하도록 돕습니다.
  3. Claude_ 파일은 Claude Code 안에, 셸 명령은 새 터미널에 붙입니다. 파일내용은 지정된 .md 파일에 저장합니다.
  4. 실제 결과와 검사 기준을 확인합니다. A8은 앱이 자동으로 보내며 수동 요청 파일이 없습니다.

D11 첫 제작에서 업무 자동화까지

그림 확대핸드북의 해당 실습

그림을 글로 읽기

  1. 바이브 코딩에서는 일상 언어로 작은 도구를 만들고 직접 눌러 다듬습니다.
  2. 에이전틱 코딩에서는 의도와 범위를 정해 AI에게 계획·도구 실행·검사를 맡깁니다.
  3. 업무 자동화에서는 검사한 도구에 새 입력을 넣어 다시 실행하고 파일 변경을 감지합니다.
  4. 매번 판단이 필요한 AI 작업과 정해진 프로그램의 반복 실행은 다릅니다. watch는 매번 Claude를 호출하지 않습니다.

D12 스킬을 배우고, 저장하고, 불러 보기

그림 확대핸드북의 해당 실습

그림을 글로 읽기

  1. name은 부를 이름, description은 하는 일과 사용할 상황입니다. 본문에는 실행 순서를 적습니다.
  2. 제공 텍스트에는 설치 요청과 SKILL.md 내용이 함께 들어 있습니다. 전체를 Claude Code 안에 붙입니다.
  3. Claude가 .claude/skills/grill-me/SKILL.md에 저장한 뒤 같은 폴더에서 다시 시작합니다.
  4. /grill-me로 인터뷰하고, 확인한 계획을 구현 요청에 사용합니다.

D13 하네스 · AI가 일할 환경을 갖추기

그림 확대핸드북의 해당 실습

그림을 글로 읽기

  1. 하네스는 새로운 프로그램 이름이 아니라 AI가 일할 환경을 갖추는 방법입니다.
  2. Excel과 계산 도구를 준비하고 CLAUDE.md에 공통 규칙을 적습니다.
  3. 보고서 스킬의 내 기준을 설정하고 제공 담당자 3명과 팀 스킬을 설치합니다.
  4. 메인 Claude가 데이터 확인, 화면 제작, 검수를 위임합니다. 결과 숫자와 화면은 직접 확인합니다.

직접 제작한 설명 도식입니다. 제품 화면이나 실행 증거를 재현한 이미지가 아닙니다.
